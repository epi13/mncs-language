# Roadmap Supplement — RFC 0031 through RFC 0037

This supplement records the cross-cutting semantic tracks added after RFC 0030 and supersedes `ROADMAP-0031-0036.md`.

The sequence is deliberately not a one-way compiler pipeline. It is a recursive evidence, realization, deployment, and operational-feedback graph:

```text
RFC 0036
Language / specification / feature evolution
        |
        v
RFC 0035
Elaboration / binding / inference / coherence
        |
        v
Existing semantic/core verification stack
        |
        v
RFC 0031
Derivation / provenance / supply-chain validity
        |
        v
RFC 0034
Controlled experiment / test / fuzz evidence
        |
        v
RFC 0032
Quantitative facts / budgets / feasibility
        |
        v
RFC 0033
Preference / risk / realization selection
        |
        v
RFC 0030
Deployment / lifecycle transition
        |
        v
RFC 0037
Operational observation / audit / runtime verification
        |
        +------------------------------+
        |                              |
        v                              v
RFC 0018 evidence appraisal      RFC 0033 value of information
        |                              |
        v                              |
Authorized response <-----------------+
```

The important new closure introduced by RFC 0037 is that a deployed realization can now produce structured operational evidence that feeds back into verification and decision-making without being conflated with either formal proof or controlled experiment evidence.

## RFC 0031 — build, derivation, reproducibility, artifact lineage, supply-chain, and attestation

[RFC 0031](rfcs/0031-machine-native-build-derivation-reproducibility-artifact-lineage-supply-chain-attestation-semantics.md) establishes explicit derivation and artifact lineage.

Primary ownership:

- artifact identity vs derivation identity vs build execution identity;
- declared dependency vs observed influence;
- hermeticity by dimension;
- repeatability vs independent reproducibility;
- bootstrap roots and compiler ancestry;
- provenance vs signatures/transparency/SBOMs;
- cache-to-derivation binding;
- untrusted build search with narrow derivation checking.

1.0 requirements include independent reproduction, undeclared-influence detection, explicit bootstrap roots, typed provenance/attestation handling, and cache-binding rejection.

## RFC 0032 — quantitative cost, resource accounting, QoS, energy, and performance

[RFC 0032](rfcs/0032-machine-native-complexity-quantitative-cost-resource-accounting-qos-energy-performance-semantics.md) establishes typed quantitative relations rather than one universal cost scalar.

Primary ownership:

- dimensions, units, metrics, and metric-specific composition algebras;
- work/span vs wall time;
- peak vs cumulative resources;
- exact/bounded/symbolic/amortized/expected/percentile quantities;
- capacity/reservation/allocation/consumption;
- workload-scoped performance evidence;
- queueing/network-calculus/WCET-style bounds;
- energy vs power vs carbon vs valuation;
- proof/build/model-call costs;
- hard quantitative feasibility before RFC 0033 selection.

1.0 requirements include work != time, peak != cumulative memory, amortized != worst-case, benchmark max != WCET, percentile != universal bound, and multiple quantitatively admissible candidates surviving into RFC 0033.

## RFC 0033 — realization search, multi-objective optimization, Pareto, risk, preference, and selection

[RFC 0033](rfcs/0033-machine-native-realization-search-multi-objective-optimization-pareto-risk-preference-selection-policy-semantics.md) establishes that feasibility and measurement do not create preference.

Primary ownership:

- hard constraints vs objectives;
- Pareto dominance/fronts;
- weighted, lexicographic, epsilon-constraint, reference-point, and satisficing policies;
- partial preferences, ties, incomparability, and unresolved decisions;
- risk/CVaR/robust/minimax-regret selection;
- safe exploration;
- value of information;
- stopping rules and optimality gaps;
- adaptive/portfolio selection;
- untrusted search with narrow selection checking.

1.0 requirements include Pareto-optimal != selected, weighted != lexicographic priority, best-known != global optimum, positive/negative value-of-information cases, and unauthorized constraint relaxation rejection.

## RFC 0034 — test, fuzz, coverage, experiment, benchmark, oracle, and empirical evidence

[RFC 0034](rfcs/0034-machine-native-test-fuzz-coverage-experiment-benchmark-oracle-empirical-evidence-semantics.md) establishes controlled experimentation as scoped evidence-producing computation.

Primary ownership:

- test case vs execution vs observation vs oracle result;
- finite support vs universal counterexample refutation;
- property/differential/metamorphic/mutation testing;
- structural/combinatorial/semantic/schedule/fault coverage;
- fuzz/symbolic/concolic search;
- counterexample shrinking and delta debugging;
- replay vs rediscovery;
- benchmark design, statistical inference, and repetition hierarchy;
- empirical applicability envelopes.

1.0 requirements include finite passing samples refusing to become proof, coverage != correctness, branch != MC/DC, bounded fuzz/schedule/fault evidence remaining bounded, and statistically significant != practically important.

## RFC 0035 — elaboration, scope, binding, inference, constraints, defaults, and coherence

[RFC 0035](rfcs/0035-machine-native-elaboration-scope-binding-inference-constraint-default-coherence-resolution-semantics.md) establishes elaboration as an evidenced relation from incomplete source to explicit semantic meaning.

Primary ownership:

- semantic binding identity and scope graphs;
- resolution witnesses;
- bidirectional/local inference;
- metavariables and typed holes;
- constraint graphs with `SAT` / `UNSAT` / `UNKNOWN`;
- interface evidence search;
- overload/coercion/default insertion;
- deterministic elaboration vs coherence;
- open-world vs closed-world resolution;
- intentional realization freedom vs missing semantics;
- untrusted AI/solver elaboration with explicit-core checking.

1.0 requirements include ambiguity without incidental-order resolution, explicit capability evidence, no manufactured authority, solver UNKNOWN != UNSAT, and semantic holes remaining distinct from realization-deferred variables.

## RFC 0036 — language, specification, feature, compatibility, migration, deprecation, and evolution

[RFC 0036](rfcs/0036-machine-native-language-specification-feature-compatibility-migration-deprecation-evolution-semantics.md) establishes immutable historical language profiles and explicit relations between evolving language worlds.

Primary ownership:

- compiler version vs language profile;
- specification revision vs semantic revision;
- edition vs core generation;
- feature semantic version vs feature status;
- language-evolution graphs;
- conservative extension;
- multidimensional compatibility;
- source/semantic/compatibility/idiomatic migration;
- deprecation lifecycle;
- mixed-profile coexistence;
- proof/evidence transport and localized evolution impact.

1.0 requirements include source-compatible but semantically incompatible change, additive-but-non-conservative feature addition, migration-path coherence, lossy migration, historical profile preservation, and AI migration accepted only through independent checking.

## RFC 0037 — observability, audit, telemetry, trace correlation, operational evidence, and runtime verification

[RFC 0037](rfcs/0037-machine-native-observability-audit-telemetry-trace-correlation-operational-evidence-runtime-verification-semantics.md) establishes operational observation as an explicit semantic and evidential layer over running systems.

### Primary ownership

- execution event vs observation vs telemetry record identity;
- observation models and completeness;
- negative evidence only under explicit completeness;
- logs, metrics, traces, profiles, audit records, and monitor outputs as distinct signal classes;
- causal links vs trace/correlation links;
- semantic observation points vs physical probe attachment points;
- instrumentation effects and observation authority;
- sampling vs pipeline loss vs retention expiry;
- raw/normalized/redacted/aggregated/inferred observation provenance;
- audit integrity vs audit truth vs audit completeness;
- runtime property monitoring and finite-prefix verdicts;
- observability and diagnosability;
- detection/localization/diagnosis/attribution/explanation distinctions;
- adaptive observation plans and value-of-information instrumentation;
- operational evidence feedback into RFC 0018/RFC 0033;
- audit of authorized operational response.

### Constitutional distinctions

The track must preserve:

```text
Event != Observation
Observation != SystemState
NoObservation != NoEvent
LogRecord != SemanticFact
TraceCorrelation != Causality
TimestampOrder != HappensBefore
Metric != EventHistory
Profile != Trace
Sampling != Loss
RetentionExpiry != EventAbsence
SignedAuditRecord != TrueStatement
AuditInclusion != AuditCompleteness
Diagnosis != CausalExplanation
MonitorVerdict != EnforcementAuthority
OperationalObservation != ControlledExperiment
```

### 1.0 threshold highlights

RFC 0037 requires:

- event/observation/telemetry identities remain distinct;
- one sampled-out event cannot become a negative fact;
- one bounded complete domain supports legitimate negative evidence;
- known observation loss mechanically weakens downstream completeness;
- trace correlation remains distinct from causality;
- one clock-skew fixture preserves happens-before despite timestamp reversal;
- one semantic observation point is bound to a realization-specific probe through a witness;
- one instrumentation perturbation case disproves automatic equivalence;
- observation authority and information-flow checks are enforced;
- head/tail sampling remain separate;
- sampling bias prevents naive population inference;
- audit integrity, truth, and completeness are demonstrated independently;
- one tamper-detection case and one authentic-but-false audit assertion exist;
- one runtime safety property yields an explicit finite counterexample;
- one liveness property remains pending/inconclusive on a finite prefix;
- monitorability is explicit;
- one weak observation plan fails diagnosability and a stronger plan succeeds;
- anomaly inference remains distinct from direct observation;
- raw/normalized/redacted/aggregated/inferred observations retain provenance;
- one adaptive observation cycle uses RFC 0033 value of information and RFC 0032 cost;
- one monitor-triggered operational action requires independent RFC 0025 authorization and produces an RFC 0037 audit trail.

## Consolidated research 1.0 integration principle

The language should not reach the research 1.0 threshold merely because individual RFC prototypes exist.

At least one end-to-end study should demonstrate:

```text
RFC 0036 exact language profile
  -> RFC 0035 explicit elaboration witness
  -> semantic/core verification
  -> RFC 0031 reproducible/provenanced artifact derivation
  -> RFC 0034 controlled empirical campaigns
  -> RFC 0032 quantitative facts and hard feasibility
  -> RFC 0033 authorized realization selection
  -> RFC 0030 lifecycle deployment
  -> RFC 0037 operational observation and runtime verification
  -> RFC 0018 operational evidence appraisal
  -> RFC 0033 value-of-information / response decision
  -> RFC 0025 authorization
  -> RFC 0030 response action
  -> RFC 0037 accountable audit record
```

No stage may launder another stage's claim class.

Specifically:

- compiler version cannot redefine historical source meaning;
- successful compilation cannot replace semantic migration evidence;
- inference cannot replace proof;
- testing cannot replace proof;
- operational telemetry cannot replace controlled experiment evidence;
- measurement cannot create preference;
- preference cannot repair invalid semantics;
- provenance cannot establish correctness;
- signature or audit integrity cannot establish semantic truth;
- trace correlation cannot establish causality;
- absence of telemetry cannot establish event absence without completeness;
- runtime monitor verdict cannot create enforcement authority;
- faster or cheaper instrumentation cannot violate observation/security requirements;
- diagnostic confidence cannot manufacture assurance;
- bounded evidence cannot become universal evidence.

## Operational-feedback milestone

RFC 0037 adds a new milestone beyond the prior static/build/experiment/deployment pipeline:

> **A deployed MNCS realization must be able to produce provenance-bearing operational evidence whose completeness and uncertainty are explicit, and that evidence must be capable of driving a separately authorized machine response without collapsing observation, diagnosis, decision, authorization, and action into one opaque agent step.**

The milestone is satisfied only when a complete fixture can reconstruct the evidence chain after the action occurs.
